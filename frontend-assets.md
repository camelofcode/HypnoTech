The asset projects write to the corresponding sibling C# project's `wwwroot`
directory, so these directory names and their placement under `src` are intentional.

## Build commands

The engine has one npm workspace and lockfile for all four asset projects. Node.js 22
or newer is required.

```sh
npm ci
npm run build:frontend
npm run check:frontend
npm run watch:frontend
```

`build:frontend` regenerates the tracked development and minified assets. The check
command performs the same compilation in memory and fails when anything in `wwwroot`
is stale, making it suitable for CI. Watch mode uses Node's native recursive watcher.

An individual project can also be built from the workspace root, for example:

```sh
npm run build -w @hypnotech/ecommerce-frontend-assets
```

The toolchain uses Dart Sass, Lightning CSS, Terser, and Browserslist. Dependency
versions are pinned in the root manifest and npm lockfile. The former nested Gulp
lockfiles and the unrelated lockfile in the Ecommerce C# project were removed so
there is only one source of dependency truth.

## Verification

At import time:

- every restored asset project was byte-for-byte identical to its original repository;
- every generated JS/CSS file already in the monorepo was byte-for-byte identical to
  the corresponding generated file in the original repository;
- concatenating the restored Media, Ecommerce, and core Frontend JS source lists
  reproduced their unminified generated bundles byte-for-byte;
- the CMS individual JS sources contain the code in its generated bundle. The Gulp glob
  places `ko.bindingHandlers.fileUpload.js` before the other CMS view-model files.

The obsolete CMS `js/script.js` and `js/script.min.js` source snapshots were removed.
Edit the individual files in `js` and `js/CmsViewModels`; generated CMS bundles belong
in `src/Cms/HypnoTech.Cms/wwwroot/js`.

The readable JavaScript bundles produced by the new builder are byte-for-byte identical
to the historical Gulp output. Minified JavaScript and compiled CSS are regenerated by
the supported toolchain, so their formatting and compression differ without changing
the public filenames or load order.
